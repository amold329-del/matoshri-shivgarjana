# SEO / indexing audit — 17 August 2026

Audited against the 22-phase brief. Method: full production build, then automated
inspection of the 18 generated HTML files, `sitemap.xml`, `robots.txt` and every
JSON-LD block, plus `tsc`, ESLint and a link-graph check.

**What I could not do from here:** fetch the live site (the sandbox reaches only
package registries), open Search Console, or run Lighthouse/axe — those need a
browser and your login. Anything about live HTTP status, redirects, www/non-www,
HTTPS behaviour, real Core Web Vitals or indexing state is therefore listed as a
manual action, not a finding. **Nothing here claims any page is indexed.**

---

## 1. Headline result

The automated audit went from **36 problems to 1**, and the one remaining is
correct behaviour (`/404/` has no canonical, which is right for a noindexed
error page).

Most of this brief was already implemented in earlier work on this project —
canonicals, per-page metadata, `NGO`+`PlaceOfWorship` organization schema with
address and geo, `Event` and `Festival` schema, `FAQPage`, `BreadcrumbList`,
`WebSite`, robots.txt with a sitemap reference and explicit AI-crawler rules,
AVIF/WebP responsive images with intrinsic dimensions, `lang="mr"`, and the
sitemap `lastmod` fix from earlier today. I did not rebuild any of it. What
follows is what was genuinely missing.

## 2. Critical

**Every page was losing four Open Graph tags.** `src/app/layout.tsx` declared
`og:type`, `og:locale` and `og:site_name`, but Next.js *replaces* the
`openGraph` object when a route declares its own — it does not deep-merge. 14 of
16 routes hand-rolled their metadata, so those four tags never reached a single
sub-page. Confirmed absent in the built HTML before, present after.

## 3. High priority

**English is effectively invisible to Google.** The homepage HTML contains 6,100
Devanagari characters and 71 Latin ones. The EN/MR toggle is client-side, so
crawlers only ever see Marathi. Every title was Marathi-only too. Queries like
"Ganesh mandal Parel Mumbai" or "Matoshree Shivgarjana" had almost nothing to
match against.

Note on what does *not* fix this: meta descriptions. Google does not use them as
a ranking signal, so padding them with English keywords would have been
theatre. Titles do count, and structured data drives entity matching — so that
is where the English went.

**The real fix is still outstanding.** Localised routes (`/en/…`, `/mr/…`) are
the only way to serve genuine English *content*, and that is a routing change I
would not ship four weeks before the festival without deliberate testing. Filed
as MCV-004 in `PROJECT-STATE.md`.

## 4. Medium / low

- Homepage title was 71 characters — truncated in results — and spent 6 of them
  on `॥ ॥` decoration instead of the locality.
- Gallery photographs were not discoverable by Google Images.
- The `WebSite` node had no Latin-script `alternateName`.

## 7. Not done, on purpose

- **No `/ganeshotsav-2026/` page.** The brief lists it as a possibility, but
  `/events/` already carries the 2026 schedule *and* the `Festival` schema, and
  `/procession/` has the route. A new page would duplicate both — a doorway page
  is exactly what the brief's Phase 19 rules out.
- **No content invented.** `/history/` is thin (233 words for 47 years) and
  `/procession/` should carry the street names as text rather than only on the
  map. Both need facts only the committee has. Tell me the text and I will place
  it.
- **No hreflang.** With one URL serving both languages there is nothing to point
  hreflang at; it becomes meaningful the day localised routes exist.
- **No design or functional change.** Titles, meta tags, JSON-LD and the sitemap
  are the only things touched. Nothing rendered on screen moved.
